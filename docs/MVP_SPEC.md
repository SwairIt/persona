# Persona MVP — что нужно чтобы юзер реально мог пользоваться

Состояние на 2026-06-04, после v1.14.

## Цель MVP

**«Я установил Persona, добавил ключ, и через 30 минут могу спросить — что я делал в 14:00, и получить осмысленный ответ»**.

Не «production-ready для тысяч юзеров». Не «зерокликс установка». А: один человек (автор) — может ежедневно использовать и получать пользу.

## Где мы сейчас

- v1.14 запущен. 472 .py файла, 252 роута, бюджет 25 МБ/день, hourly cards + daily pins, Gemini provider, мик-toggle.
- 424 теста зелёных, 34 красных — половина это мёртвые тесты для удалённых фич, половина настоящие.
- /ask существует, но никогда не вернул осмысленный ответ юзеру (нет ключа LLM, нет UI-нудж'а добавить ключ).
- Mac агент работал в curl-тесте, но не подтверждено что демон реально шлёт каптуры.
- Нет full-export — если юзер захочет уйти, данные у него не унесутся.
- OCR + embeddings выключены по умолчанию — а без них /ask видит только app_name + window_title, не сам контент.

## MVP scope (что я сделаю в этом проходе)

### 1. Тесты до зелёного-ish (≤5 fails)

34 fails сейчас. План:
- **Удалить мёртвые** (`test_v033 tag_trend`, `test_v047 audit_rss`, `test_v046 tag_colour`, `test_v018 app_overrides`, `test_v029 time_on_app`, `test_v028 keywords_api_shape`, `test_v050 feature_index`, `test_v05_routes apps_index`, `test_v032 pdf_export_route`, etc) — роуты удалены, тесты на удалённые роуты не нужны
- **Поправить настоящие**: test_home_renders (303→200 redirect), test_share_collection (auth изменился), test_capture_now (mss на сервере)
- **xfail mss-зависимые на Server 2019** — нет микрофона/некоторые draw, не должны падать в CI

Цель: 458+ passes, ≤5 fails.

### 2. Setup wizard: ткнуть в LLM-ключ

Сейчас новый юзер видит timeline без LLM. /ask молча падает в LLMNotConfigured. Нужно:
- Setup wizard step «Connect your LLM» → дефолт **Gemini** (free), кнопка «открыть aistudio.google.com», поле для ключа
- Баннер на главной если ключа нет: «Add LLM key to unlock /ask»
- Тест ключа («Send test ping») перед сохранением — отлавливает опечатки

### 3. /memory page — где видны карточки и pins

Сейчас hourly cards и daily pins существуют в DB, но юзер их не видит. Нужно:
- `/memory` route с табами: «Today's hours», «Last 30 days», «Long-term pins»
- Каждая карточка кликабельная, показывает приложения, top-words, transcript-excerpt
- Поиск/фильтр по дате

### 4. Full-export endpoint

`GET /api/export/everything.zip` — стриминг ZIP с:
- persona.db (SQLite файл)
- thumbnails/ (все WebP)
- audio_segments/ (все .opus)
- agent/ (загруженные с Mac)
- README с описанием схемы

Юзер может в любой момент скачать и хранить вне приложения.

### 5. OCR + embeddings: one-click «power mode»

Сейчас спрятано в `/settings`. Нужно:
- На `/setup` или `/settings` — одна заметная карточка «Включить мощный поиск» → включает `ocr_enabled=true` + `embeddings_enabled=true` + объясняет цену (CPU, +200 МБ для модели)
- Сразу запускает backfill OCR на последние 7 дней (фоновая задача)

### 6. README что работает

Сейчас README не покрывает v1.13/v1.14. Нужно:
- «Quick start» (5 шагов: clone, uv sync, persona-setup, open browser, add LLM key)
- Раздел «Privacy» (что хранится локально, что уходит в LLM)
- Mac agent: как поставить + проверить
- Раздел про бюджет 25 МБ/день и tier'ы памяти

### 7. Финальная верификация

- pytest зелёный (≤5 fails допустимо)
- uvicorn стартует чисто
- /memory открывается без 500
- /api/export/everything.zip отдаёт валидный zip
- /ask с Gemini ключом возвращает осмысленный ответ
- Mac agent: написать инструкцию для юзера как проверить (без меня)

## Что НЕ делаю в этом проходе

- Search-консолидация 5→1 (полировка, не MVP)
- LLM-enrichment hourly cards (works без)
- Webhooks, мульти-юзер, prod-deployment
- Mobile app
- Backup в облако (full-export локальный — достаточно)
- Поиск консолидация (~700 LOC), CSV-консолидация — отдельный sprint

## Стратегические заметки на будущее (после MVP)

**Главная архитектурная нелепость**: проект расположен между «личный инструмент» и «open-source продукт». 252 роута — это для продукта. Спайки (search × 5, csv × 8) — это для прототипа который никогда не убирался. Нужно решить:

- **A.** «Это мой личный инструмент, OS на гитхабе для прозрачности, но в проде один юзер (я)» → можно срезать 60% кода, упростить setup, выкинуть Tier-2 фичи (saved searches, share collections, reading list, focus mode, reminders). Они никому не нужны если юзер один.
- **B.** «Это серьёзный OS продукт, я буду растить community» → нужен прод-deployment, multi-tenancy, аккаунты, оплата за hosted версию, нормальная docs-сайт.

Сейчас проект делает **B без B-инфраструктуры**. Решение пораздумать после MVP. Я склоняюсь к A — экономия времени огромная, и в любой момент можно перейти к B если будут юзеры.

**Долгосрочная компрессия (то что мы обсуждали):**
- Tier 5 daily_pin реализован — 200 байт/день навсегда. Это базовый каркас.
- Над этим — нужно: weekly_pin (1 КБ/неделя), monthly_pin (5 КБ/месяц), entity_graph (люди/проекты упомянутые ≥3 раз). Эти будут после MVP когда у юзера накопится хотя бы 30 дней данных.

**LLM-narrative enrichment**:
- hourly_card.llm_enriched=0 везде сейчас. Когда юзер реально начнёт использовать /ask и поймёт что эвристика «top-3 apps + keywords» слабовата — тогда добавляем LLM-pass который читает hourly_card + 24 связанных скриншота и пишет narrative («между 14:00 и 15:00 ты обсуждал с Денисом архитектуру X»). Стоит копейки на Gemini Flash. Но **не сейчас** — сначала юзер должен понять что эвристика недостаточна.
