# Telegram-агент Persona

Telegram — отдельный интерфейс того же аккаунта Persona. Он использует
существующие chat sessions, выбранный системный промпт, профиль пользователя,
долговременную память, recall прошлых чатов и контекст активности.

## Безопасность

- По умолчанию бот никому не отвечает.
- Личные сообщения разрешены только одному привязанному Telegram user id.
- Привязка всегда относится к owner user id сайта.
- Группы закрыты, пока владелец лично не отправит в группе `/allow_here`.
- Участники разрешённой группы могут обратиться к Persona, но не получают
  доступа к сайту и не могут разрешать другие группы.
- Когда к боту обращается обычный участник разрешённой группы, приватные профиль,
  память других чатов и активность владельца не подмешиваются. Полный контекст
  Persona доступен только сообщению привязанного владельца. Помните: ответ
  владельцу видят остальные участники группы, поэтому личные вопросы безопаснее
  задавать боту в личном чате.
- Инструменты, меняющие сайт, файлы и внешние системы, через Telegram пока
  отключены. Чат, общая память и анализ активности работают.
- Токен бота не записывается в БД и не попадает в логи.

Для production безопаснее явно задать владельца:

```dotenv
PERSONA_TG_BOT_TOKEN=...
PERSONA_TG_OWNER_USER_ID=123456789
PERSONA_TG_ALLOWED_CHAT_IDS=
```

`PERSONA_TG_OWNER_USER_ID` — числовой Telegram id владельца. При таком
варианте дополнительная привязка не нужна. `PERSONA_TG_ALLOWED_CHAT_IDS` —
опциональный список заранее разрешённых групп через запятую.

Если id не задан, используется одноразовая привязка. На машине, где работает
сайт и лежит его БД:

```powershell
powershell -ExecutionPolicy Bypass -File .\ops\persona_telegram_worker.ps1 -Pair
```

Скрипт покажет одноразовую команду `/claim ...`, после чего сразу запустит
worker. Отправьте команду боту в личном чате. Код удаляется из БД после
успешной привязки. Не пересылайте и не сохраняйте его в общих логах.

Последующие запуски:

```powershell
powershell -ExecutionPolicy Bypass -File .\ops\persona_telegram_worker.ps1
```

Supervisor автоматически перезапускает процесс после неожиданного выхода, а
сам worker переподключается к Telegram с экспоненциальной задержкой.

Для установки в автозапуск Windows и немедленного старта выполните **одну**
команду (первый раз — с безопасной привязкой):

```powershell
powershell -ExecutionPolicy Bypass -File .\ops\install_persona_telegram_autostart_windows.ps1 -Pair
```

Будет создана отдельная задача `PersonaTelegramWorker` с запуском при входе
текущего пользователя и автоматическим рестартом. Скрипт не требует прав
администратора и не меняет задачу веб-сервера Persona.

Без PowerShell:

```text
uv run python -m app.integrations.telegram
```

## Группы

1. Добавьте бота в группу.
2. Владелец пишет `/allow_here`.
3. Позвать агента можно через `@имя_бота`, ответ на его сообщение или
   `/persona вопрос`.
4. `/deny_here` немедленно закрывает группу, `/new` создаёт новую ветку чата.

Чтобы Persona видела и сохраняла **всю** переписку разрешённой группы, а не
только команды и упоминания, отключите Privacy Mode у бота через BotFather:
`/setprivacy` → выбрать бота → `Disable`. Это делает сам владелец Telegram;
программно изменить настройку BotFather нельзя.

## Локальный LLM worker

Если сайт использует провайдер `worker`, локальная модель должна быть
подключена отдельным исходящим worker. Он уже имеет reconnect и auto-restart:

```powershell
powershell -ExecutionPolicy Bypass -File .\ops\persona_llm_worker.ps1
```

Telegram worker должен работать рядом с серверной БД Persona, а LLM worker —
на ПК с Ollama. Это разные процессы и разные границы доверия.
