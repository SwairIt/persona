# Telegram-агент Persona

Telegram — отдельный интерфейс того же аккаунта Persona. Личный чат владельца
использует общую Persona и её память. Каждая группа получает отдельную,
изолированную ветку без приватного профиля, памяти других чатов, активности и
инструментов.

## Безопасность

- По умолчанию бот никому не отвечает.
- Личные сообщения разрешены только одному привязанному Telegram user id.
- Привязка всегда относится к owner user id сайта.
- Группы закрыты, пока владелец лично не отправит в группе `/allow_here`.
- Участники разрешённой группы могут обратиться к Persona, но не получают
  доступа к сайту и не могут разрешать другие группы.
- Любое сообщение группы, включая сообщение владельца, использует только
  историю этой группы. Приватный профиль, другие разговоры, экранная активность,
  секреты и инструменты всегда отключены.
- В личном чате владельца разрешённые инструменты доступны через безопасный
  автономный allowlist.
- Токен бота не записывается в БД и не попадает в логи.

Для production безопаснее явно задать владельца:

```dotenv
PERSONA_TG_BOT_TOKEN=...
PERSONA_TG_OWNER_USER_ID=123456789
PERSONA_TG_ALLOWED_CHAT_IDS=
```

`PERSONA_TG_OWNER_USER_ID` — числовой Telegram id владельца. При таком
варианте дополнительная привязка не нужна. `PERSONA_TG_ALLOWED_CHAT_IDS` —
опциональный список заранее разрешённых групп через запятую.

Если id не задан, используется одноразовая привязка. На машине, где работает
сайт и лежит его БД:

```powershell
powershell -ExecutionPolicy Bypass -File .\ops\persona_telegram_worker.ps1 -Pair
```

Скрипт покажет одноразовую команду `/claim ...`, после чего сразу запустит
worker. Отправьте команду боту в личном чате. Код удаляется из БД после
успешной привязки. Не пересылайте и не сохраняйте его в общих логах.

Последующие запуски:

```powershell
powershell -ExecutionPolicy Bypass -File .\ops\persona_telegram_worker.ps1
```

Supervisor автоматически перезапускает процесс после неожиданного выхода, а
сам worker переподключается к Telegram с экспоненциальной задержкой.

Для установки в автозапуск Windows и немедленного старта выполните **одну**
команду (первый раз — с безопасной привязкой):

```powershell
powershell -ExecutionPolicy Bypass -File .\ops\install_persona_telegram_autostart_windows.ps1 -Pair
```

Будет создана отдельная задача `PersonaTelegramWorker` с запуском при входе
текущего пользователя и автоматическим рестартом. Скрипт не требует прав
администратора и не меняет задачу веб-сервера Persona.

Без PowerShell:

```text
uv run python -m app.integrations.telegram
```

## Группы

1. Добавьте бота в группу.
2. Владелец пишет `/allow_here`.
3. Persona учитывает каждое доставленное обычное сообщение и сама решает,
   полезно ли ответить. Решения и ответы ограничены таймаутами и cooldown, чтобы
   бот не спамил.
4. Для гарантированного немедленного ответа используйте `@имя_бота`, ответ на
   сообщение бота или `/persona вопрос`.
5. `/deny_here` немедленно закрывает группу, `/new` создаёт новую ветку чата.

Чтобы Persona видела и сохраняла **всю** переписку разрешённой группы, а не
только команды и упоминания, отключите Privacy Mode у бота через BotFather:
`/setprivacy` → выбрать бота → `Disable`. Это делает сам владелец Telegram;
программно изменить настройку BotFather нельзя.

После изменения Privacy Mode удалите бота из группы и добавьте снова: Telegram
может не применить новый режим к уже добавленному участнику. При включённом
Privacy Mode Telegram вообще не доставляет боту большую часть обычных
сообщений, поэтому Persona не сможет их сохранить или оценить.

## Нативные действия Telegram

Persona может выбирать действие по обычной фразе, без специальных команд:

- поставить подходящую реакцию на текущее сообщение;
- отправить фото, документ, аудио, видео, GIF/animation, voice или sticker по
  `file_id` текущего вложения либо по HTTPS-ссылке из запроса владельца;
- создать опрос, отправить геолокацию, контакт или Telegram dice;
- скопировать текущее сообщение;
- по явной просьбе владельца изменить или удалить последнее сообщение,
  отправленное самим ботом.

Входящие фото передаются мультимодальной модели, если выбранный LLM их
поддерживает. Небольшие `text/*` документы читаются как текст. Voice/audio
скачиваются с ограничением размера и передаются локальному Whisper, когда он
установлен; без доступного STT Persona всё равно видит безопасные метаданные
вложения.

Модель никогда не выбирает произвольный `chat_id` или `message_id`. Медиа можно
взять только из текущего сообщения или из HTTPS-ссылки, дословно присутствующей
в запросе владельца. Изменение, удаление и остальные расширенные действия
разрешены только владельцу в личном чате. В группе доступны текст, реакции и
изолированный анализ вложений; приватная память и инструменты по-прежнему
отключены. Административные операции, платежи и действия от имени личного
Telegram-аккаунта намеренно не выдаются модели.

## Локальный LLM worker

Если сайт использует провайдер `worker`, локальная модель должна быть
подключена отдельным исходящим worker. Он уже имеет reconnect и auto-restart:

```powershell
powershell -ExecutionPolicy Bypass -File .\ops\persona_llm_worker.ps1
```

Telegram worker должен работать рядом с серверной БД Persona, а LLM worker —
на ПК с Ollama. Это разные процессы и разные границы доверия.

## Как пользоваться ботом

### Личный чат владельца

1. Откройте личный диалог с ботом и отправьте `/start` или `/help`.
2. Пишите обычным текстом, как в чате на сайте. Бот использует ту же Persona,
   долговременную память, recall и контекст владельца.
3. В личном чате владельца доступны разрешённые инструменты Persona. Их
   выполнение ограничено allowlist, числом раундов и размером результата;
   служебные tool-вызовы и сырые результаты не показываются в ответе.
4. `/new` создаёт новую ветку разговора для текущего Telegram-чата, но не
   удаляет общую долговременную память.

Если локальный ПК с Ollama выключен, спит или вышел из учётной записи Windows,
бот не сможет получить ответ от локальной модели. После пробуждения ПК
`PersonaLLMWorker` запускается через локальную Scheduled Task; повторно
устанавливать его не нужно.

### Группа

1. Добавьте бота в группу.
2. Владелец пишет `/allow_here`.
3. Пишите как обычно: Persona сохраняет доставленные сообщения и иногда
   подключается сама, если её ответ действительно полезен.
4. `@имя_бота`, ответ боту и `/persona ваш вопрос` обходят ambient-cooldown и
   дают немедленный ответ.
5. `/deny_here` снова закрывает группу, `/new` создаёт новую ветку группы.

Групповой режим всегда изолирован: даже сообщения владельца в группе не
получают приватную память владельца и не запускают инструменты. Для личных
данных и действий используйте личный диалог с ботом.

Чтобы бот видел обычные сообщения группы, а не только команды и упоминания,
в BotFather нужно выполнить `/setprivacy`, выбрать бота и нажать `Disable`,
после чего удалить бота из группы и добавить снова.
