# Петля мышления, настройки всего и полный доступ

Дата: 2026-07-30
Статус: утверждён владельцем, к реализации

## Задача

1. Persona должна **думать сама**: после разговора ставить себе вопрос, возвращаться
   к нему, развивать мысль цепочкой и закрывать выводом.
2. Всё это должно **настраиваться на сайте**, а не быть зашито в код.
3. Настройки **Telegram** — какие чаты читать, где отвечать, что разбирать —
   тоже на сайте, а не командами внутри чата.
4. Чат `-5026288199` («персик, клодик, индик») — полный доступ: отвечать и
   разбирать историю.
5. У ассистента должен быть **полный доступ ко всему, в первую очередь к интернету**.

## Что уже построено и переиспользуется

Значительная часть существует. Новый код пишется только там, где его нет.

| Возможность | Где | Состояние |
|---|---|---|
| Persona пишет первой, сама решает молчать или нет | `app/application/autowake/impulses.py` | работает; кулдаун 30 мин, 12/сутки |
| Durable-очередь доставки с лизами, at-least-once | `app/application/autowake/service.py` | работает |
| Классификация приватности, fail-closed | `app/domains/autowake/policy.py` (`SourceScope`) | работает |
| «Сон»: разбор разговоров, продвижение в память | `app/chat/reflection.py` (`run_dream_cycle`) | работает |
| Гейт тишины | `app/chat/reflection.py` (`_is_quiet`, 60 мин) | работает |
| Чтение истории чата юзер-аккаунтом (Telethon) | `app/integrations/telegram/pinned_ingest.py` | работает, но выбор чатов завязан на «закреплён» |
| Инструменты: `web_search`, `web_browse`, `fetch_json` | `app/mcp/builtin_tools.py` | работают, в Telegram заглушены эвристикой |
| `install_mcp`, `install_skill`, `run_shell` | `app/mcp/builtin_tools.py` | работают, из Telegram недоступны |
| SSRF-защита URL | `app/mcp/builtin_tools.py` (`_url_is_safe`) | работает |

**Чего нет:** замыкания петли — мысль уходит наружу в Telegram, но никогда не
возвращается Persona на вход. Это ядро задачи.

## Срез A — петля мышления

### Данные

Новая таблица `persona_thought`:

| Поле | Смысл |
|---|---|
| `chain_id` | цепочка размышления |
| `step_no` | номер шага в цепочке |
| `kind` | `seed` / `step` / `conclusion` |
| `seed_kind` | `know_you` / `unfinished` / `self_check` / `alive` |
| `text` | сама мысль |
| `source_scope` | наследуется от источника посева (`SourceScope`) |
| `source_session_id` | из какого разговора вырос посев |
| `status` | `open` / `closed` / `abandoned` |
| `created_at` | время |

### Посев

Разговор затих → producer просит модель написать **одну вещь**, которую она хочет
обдумать. Тип посева выбирается по кругу из включённых владельцем:

| Тип | Вопрос себе |
|---|---|
| `know_you` | что нового я поняла про владельца и что из этого следует |
| `unfinished` | какой вопрос остался без ответа — доведи его |
| `self_check` | где я в своих ответах наврала или недопоняла |
| `alive` | свободная мысль, без прикладной цели |

### Цепочка

Открытая цепочка подаётся модели **на вход** как контекст, она делает следующий шаг.
Это и есть замыкание петли.

Потолок шагов — настройка (см. срез B). В режиме «модель решает сама» модель на
каждом шаге отвечает, продолжать или закрывать, и её решение выполняется; работает
только аварийный предел из настроек, защищающий от зависшей цепочки.

Достигнут потолок → модель **обязана** написать вывод (`kind='conclusion'`),
цепочка закрывается.

### Когда думает

Только в простое: тишина по `_is_quiet` **и** нет активной генерации.

**Вытеснение:** пришло сообщение владельца → текущий шаг бросается, цепочка
остаётся `open` и продолжится в следующее окно тишины. Владелец всегда важнее —
это инвариант, а не оптимизация.

Плюс суточный бюджет шагов из настроек.

### Куда девается

1. **Дневник** `/thoughts` — основной сток. Видны цепочки, шаги, выводы, статус.
2. **Память** — только `conclusion`, и только через существующий порог продвижения
   из `reflection.py`. Не всякая мысль достойна запоминания.
3. **Чат — изредка.** Вывод может быть помечен «стоит сказать» и уйти в
   существующий `PersonaImpulseProducer`. Его кулдаун и суточный лимит не
   изменяются: «иногда» гарантировано механикой, а не уговорами модели.

### Граница приватности

Цепочка наследует `SourceScope` источника. Мысль, выросшая из группового
разговора, **никогда** не попадает в приватный дневник владельца как приватная и
**никогда** не уходит в автосообщение — `SAFE_SOURCE_SCOPES` групповое не
пропускает. Ограничение уже существует и не обходится.

Причина жёсткости: иначе получится машина, пересказывающая владельцу чужие
разговоры под видом собственных размышлений.

## Срез B — страница `/settings/thinking`

| Настройка | Тип | Значение по умолчанию |
|---|---|---|
| Думать | вкл/выкл | выкл |
| Режим потолка | число / «модель решает сама» | число |
| Потолок шагов | 1..50 | 5 |
| Аварийный предел | 1..500 | 50 |
| Суточный бюджет шагов | 1..1000 | 60 |
| Типы посева | 4 галочки | все включены |
| Может писать в чат | вкл/выкл | выкл |

Плюс **живое состояние** на той же странице, иначе система непрозрачна:
потрачено шагов сегодня, открытая цепочка, время следующего окна тишины,
текущий кулдаун импульсов.

Хранение — kv, как остальные настройки проекта.

Страница регистрируется в `app/web/routes/settings_hub.py` → `_CATEGORIES`
(правило проекта: иначе пункт недоступен из UI).

## Срез C — страница `/settings/telegram-chats`

Сейчас доступ к группам раздаётся командами **внутри чата**, а исторический разбор
включается тем, **закреплён ли чат** в Telegram владельца. Обе ручки спрятаны от
владельца. Переносятся на сайт.

Список всех чатов, которые Persona видела, по каждому:

- **Режим**: `отвечать` / `только читать` / `игнорировать`
- **Разбирать историю**: вкл/выкл — Telethon-импорт с ночным анализом

Существующий kv `telegram_allowed_chat_ids` остаётся источником истины для режима
«отвечать», чтобы транспорт не пришлось переучивать. Выбор чатов для Telethon
перестаёт зависеть от признака «закреплён» и берётся из этой страницы.

Страница также регистрируется в `_CATEGORIES`.

## Срез D — включить чат `-5026288199`

Режим `отвечать` + `разбирать историю`.

Факты, установленные при проектировании:

- Чат уже в `telegram_allowed_chat_ids` — новые сообщения записываются.
- `telegram_pinned_chat` — **0 строк**: историю никто ни разу не читал.
- `PERSONA_TG_USER_API_ID` и `PERSONA_TG_USER_API_HASH` в `.env` **заданы**.
- `PERSONA_TG_SESSION` отсутствует — сессию Telethon нужно один раз создать
  интерактивно (код подтверждения от Telegram). Это действие владельца, кодом не
  обходится.

Историю читает **юзер-аккаунт**, а не бот: Bot API не отдаёт старые сообщения
в принципе.

В чате участвуют агенты Клод и Инди. Их сообщения разбираются как обычное
групповое содержимое и остаются под `SourceScope.GROUP`.

## Срез E — полный доступ

**Личный чат владельца:** полный набор инструментов без эвристик. Удаляется
`_owner_tools_needed` из `worker.py` — она глушила инструменты на коротких
сообщениях («найди фото кота» короче порога 160 символов → инструментов нет).

**Интернет:** `web_search`, `web_browse`, `fetch_json` доступны всегда, включая
группы. SSRF-защита `_url_is_safe` остаётся — она защищает от обращений во
внутреннюю сеть, а не ограничивает интернет.

**Исполняющие инструменты** (`install_mcp`, `install_skill`, `run_shell`,
`run_mac`): доступны владельцу; из групп запрещены полностью. Подтверждение
владельца кнопкой сохраняется — это осознанный выбор владельца, сделанный ранее
при проектировании; аргументы читаются из БД по `id`, а не из `callback_data`,
иначе подтверждение бессмысленно.

Причина, по которой группы отделены: вход модели включает недоверенный текст
других участников, и исполнение кода по их тексту — путь от инъекции до RCE на
машине владельца. Владелец в правах не ограничивается.

## Тестирование

- Цепочка: посев → шаги → принудительный вывод на потолке; в режиме «модель решает
  сама» решение модели выполняется, аварийный предел срабатывает только при
  зависании.
- Вытеснение: сообщение владельца во время шага → шаг брошен, цепочка `open`.
- Бюджет: суточный лимит шагов не превышается.
- Приватность: цепочка из группового посева не попадает в приватный дневник и не
  уходит в автосообщение.
- Настройки: выключенное «думать» полностью останавливает воркер; выключённый тип
  посева не выбирается.
- Telegram-чаты: смена режима меняет поведение транспорта; `игнорировать`
  не мешает записи истории.
- Инструменты: короткое сообщение владельца получает инструменты; группа получает
  только читающие; исполняющий инструмент из группы отклоняется независимо от
  формулировки.

## Порядок работ

A+B (петля и её настройки) → C+D (чаты и включение) → E (доступ).
Каждый срез — отдельный план, коммит с бампом версии, пуш.

## Сознательно не делается

- Второй канал доставки в обход autowake.
- Продвижение в память всех мыслей подряд, а не только выводов.
- Обход `SAFE_SOURCE_SCOPES` для группового содержимого.
- Автоматическая установка MCP без подтверждения владельца.
