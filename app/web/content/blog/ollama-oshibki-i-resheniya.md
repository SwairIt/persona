«Error: could not connect to ollama app, is it running?», «Error: model requires more system memory than is available», «no compatible GPUs were discovered» — три сообщения, за которыми стоят три совершенно разные проблемы и три разных решения.

Общего совета здесь нет. Есть соответствие между текстом сообщения и причиной, и оно почти однозначное. Ниже — таблица этого соответствия и разбор каждого случая.

Тексты сообщений приводятся в том виде, в каком они встречались на момент написания; **формулировки между версиями меняются, поэтому ориентируйтесь на смысл, а не на дословное совпадение**.

## Быстрая проверка

Две команды отсекают примерно половину обращений.

```
ollama --version
ollama ps
```

Первая отвечает на вопрос «установлено ли и запущена ли служба». Если она молчит или сообщает, что команда не найдена, проблема в установке или в переменной PATH, и дальше читать нужно только первый раздел.

Вторая показывает, что загружено в память прямо сейчас и на чём считается. Колонка `PROCESSOR` со значением `100% CPU` при наличии видеокарты — это уже диагноз, хотя никакой ошибки при этом не выводилось.

Полный журнал службы на Linux:

```
journalctl -u ollama -n 200 --no-pager
```

## Причина 1: служба не запущена

**Признак:** `could not connect to ollama app, is it running?` или `connection refused` при любой команде.

**Проверка:**

```
systemctl status ollama
ss -tlnp | grep 11434
```

**Решение:** запустить службу (`systemctl start ollama` на Linux, запустить приложение на Windows и macOS). Если служба падает сразу после старта, смотрите журнал — причина будет там, а не в клиенте.

Отдельный случай: `bind: address already in use`. Служба уже запущена, и вы пытаетесь поднять вторую. Типично после ручного `ollama serve` при работающем системном сервисе.

## Причина 2: команда не найдена после установки

**Признак:** `ollama: command not found` или `не является внутренней или внешней командой`.

**Проверка:** открыть новый терминал и повторить. Проверить, что каталог установки есть в PATH.

**Решение:** перезапустить терминал, а на Windows — иногда и сеанс пользователя, чтобы система подхватила новую переменную PATH. Если не помогло — переустановить, следя за тем, чтобы установщик отработал без ошибок.

## Причина 3: не хватает памяти

**Признак:** `model requires more system memory (X GiB) than is available (Y GiB)`, либо запуск обрывается без внятного текста, либо процесс runner завершается аварийно.

**Проверка:**

```
nvidia-smi --query-gpu=memory.used,memory.total --format=csv
free -g
```

**Решение:** по порядку — освободить занятую память, уменьшить контекст, включить квантизацию KV-кэша, взять более жёсткую квантизацию весов. Полная последовательность с оценкой потерь на каждой ступени — в материале о том, [что делать, если модель не влезает в память](/blog/llm-ne-vlezaet-v-pamyat-chto-delat).

Обратите внимание на слово `system` в тексте ошибки: речь может идти об оперативной памяти, а не о видеопамяти. Ollama проверяет обе.

## Причина 4: видеокарта не найдена

**Признак:** в журнале `no compatible GPUs were discovered`, либо ошибки нет вовсе, но `ollama ps` показывает `100% CPU`.

**Проверка:**

```
nvidia-smi
rocminfo | grep -i gfx
```

**Решение:** зависит от вендора. Для NVIDIA — установить или обновить драйвер. Для AMD — карта может не поддерживаться текущей версией вычислительного стека; иногда помогает подмена версии архитектуры через переменную окружения. Для встроенной графики — она может не поддерживаться вовсе.

Это самая коварная категория, потому что ошибки как таковой нет: модель работает, просто в разы медленнее.

## Причина 5: модель не скачивается

**Признак:** `pull model manifest: file does not exist`, `max retries exceeded`, `digest mismatch`.

**Проверка:**

```
ollama pull qwen2.5:7b
curl -I https://registry.ollama.ai
```

**Решение:** первое сообщение означает опечатку в имени или несуществующий тег — проверьте название в каталоге. Второе — сетевую проблему: прокси, файрвол, нестабильное соединение. Третье — повреждённую загрузку: повторите скачивание, при повторении удалите частично скачанные данные.

## Причина 6: модель не поддерживается версией

**Признак:** `unsupported model architecture`, `unknown model architecture` при попытке запустить свежую модель или свой файл GGUF.

**Проверка:** сверить версию (`ollama --version`) с датой выхода модели.

**Решение:** обновить Ollama. Поддержка каждого нового семейства моделей добавляется отдельно, и файл при этом целый — просто ваша версия о такой архитектуре не знает.

## Причина 7: модель отвечает странно

**Признак:** ошибки нет, но модель дописывает ваши реплики, не останавливается, игнорирует системный промпт.

**Проверка:**

```
ollama show --template <модель>
```

**Решение:** проблема в шаблоне чата. Если вы создавали свой пресет и писали Modelfile с нуля — вы, скорее всего, потеряли шаблон базовой модели. Пересоздайте файл, начав с вывода `ollama show --modelfile`.

## Таблица: симптом, причина, проверка

| Сообщение или симптом | Причина | Проверочная команда |
|---|---|---|
| `could not connect to ollama app` | служба не запущена | `systemctl status ollama` |
| `bind: address already in use` | служба уже запущена | `ss -tlnp \| grep 11434` |
| `command not found` | PATH не обновлён | новый терминал, `ollama --version` |
| `requires more system memory` | не хватает памяти | `nvidia-smi`, `free -g` |
| `no compatible GPUs were discovered` | драйвер или неподдерживаемая карта | `nvidia-smi`, `rocminfo` |
| `ollama ps` показывает `100% CPU` | молчаливый откат на процессор | `ollama ps` |
| `file does not exist` при pull | опечатка в имени модели | `ollama list`, каталог моделей |
| `max retries exceeded` | сеть или прокси | `curl -I https://registry.ollama.ai` |
| `unsupported model architecture` | устаревшая версия Ollama | `ollama --version` |
| модель дописывает ваши реплики | сломан шаблон чата | `ollama show --template` |
| первый ответ идёт долго | модель выгружена из памяти | `ollama ps` |
| недоступна с другой машины | слушает только локальный адрес | `ss -tlnp \| grep 11434` |

Что здесь смотреть: третий столбец. Почти каждая строка проверяется одной командой, и это отличает диагностику от гадания. Если проверка не подтвердила гипотезу — переходите к следующей строке, а не пробуйте решение наугад.

Две последние строки — не ошибки, а ожидаемое поведение. Модель выгружается из памяти после периода простоя, и первый запрос после паузы ждёт её загрузки; настраивается это временем удержания. Сетевой доступ по умолчанию закрыт, и открывается он отдельно — с оговоркой, что у Ollama нет авторизации, о чём подробно в материале о [настройке доступа к Ollama по сети](/blog/ollama-po-seti-nastroyka).

## Если ничего не помогло

Включите подробный журнал и перезапустите службу:

```
OLLAMA_DEBUG=1 ollama serve
```

В подробном режиме видно, какой бэкенд выбран, сколько слоёв ушло на видеокарту и на чём именно оборвался запуск. Это то место, где находятся причины, не попавшие в таблицу выше.

Если проблема воспроизводится в контейнере, но не на хосте (или наоборот) — она почти наверняка в пробросе устройств, а не в самой Ollama; разбор в материале о [запуске Ollama в Docker](/blog/ollama-v-docker).

Если ошибок нет, всё запускается, но работает медленно — это отдельная задача с отдельным деревом проверок, описанным в материале о том, [почему локальная модель тормозит](/blog/medlennaya-generatsiya-prichiny).

И наконец, если установка выглядит повреждённой — переустановка действительно помогает, но только после того, как вы прошли проверки выше. Иначе вы переустановите и получите ту же ошибку, потратив час. Базовый порядок установки — в [гайде по запуску моделей через Ollama](/blog/ollama-lokalnyy-zapusk).

## Частые вопросы

### Почему Ollama не видит мою видеокарту?

Три типичные причины: не установлен или устарел драйвер, карта не поддерживается вычислительным стеком, либо инструмент собран без нужного бэкенда. Проверяется командой `nvidia-smi` для NVIDIA или `rocminfo` для AMD — если они не видят карту, Ollama тоже не увидит.

### Где лежат логи Ollama?

На Linux — в журнале systemd, доступны через `journalctl -u ollama`. На Windows и macOS — в каталоге данных приложения; точный путь зависит от версии. Подробный режим включается переменной `OLLAMA_DEBUG=1`.

### Что делать при ошибке о нехватке памяти?

Сначала посмотреть, чем занята память: часто дело не в модели, а в другом процессе. Затем по порядку сокращать расход — контекст, квантизация кэша, квантизация весов. Смена модели на меньшую — последний шаг, а не первый.

### Почему модель работает, но очень медленно?

Скорее всего, часть слоёв или все считаются процессором. Ошибки при этом не будет: откат происходит молча. Проверяется командой `ollama ps` — колонка `PROCESSOR`.

### Поможет ли переустановка?

Помогает при повреждённой установке и при проблемах с PATH. Не помогает при нехватке памяти, отсутствии драйвера, неподдерживаемой карте и устаревшей версии — то есть в большинстве случаев. Сначала проверка, потом переустановка.

### Как удалить всё и начать заново?

Удалить приложение штатным способом, затем каталог с моделями (он отдельный и переживает переустановку). Помните, что вместе с ним удалятся все скачанные веса — это десятки гигабайт, которые придётся качать снова.
