Обычная развилка для того, кто хочет локальную модель с окном, а не с терминалом: взять отполированное закрытое приложение или открытое, но грубее. Jan — второй вариант. Его исходный код опубликован, и это единственная причина выбирать его вместо более удобных конкурентов.

Формулировка звучит резко, но честно. Если открытость исходников для вас не аргумент, а просто приятная строчка, Jan вас, скорее всего, разочарует: часть привычных настроек придётся искать, часть — не найдётся вовсе. Если аргумент — читайте дальше, там есть за что платить неудобством.

Факты о Jan и о LM Studio проверялись 25.08.2026; оба проекта развиваются, и таблицу различий стоит перепроверять.

## Что понадобится

- **Windows, macOS или Linux** в 64-битном варианте. Под Linux распространяется в виде AppImage и пакетов.
- **Файл модели** — либо из встроенного каталога, либо свой GGUF с диска.
- **Понимание своих ограничений по памяти.** Приложение помогает меньше, чем LM Studio: подсказки о том, влезет ли модель, скромнее. Считайте сами: вес файла плюс память под контекст плюс примерно гигабайт накладных расходов. Общий маршрут локального запуска описан в [руководстве по запуску LLM локально](/blog/kak-zapustit-llm-lokalno).

## Шаг 1. Установка и первый запуск

Скачайте сборку для своей системы с сайта проекта и установите обычным способом. На Linux образу AppImage нужно выдать право на исполнение.

При первом запуске приложение предложит скачать модель. Отказаться и сначала осмотреться — нормальный ход: интерфейс делится на список диалогов слева, само окно диалога и панель настроек справа.

## Шаг 2. Скачать модель или подключить свою

Во встроенном каталоге модели перечислены с указанием размера и рекомендацией по памяти. Список короче, чем поиск по открытому каталогу моделей в LM Studio, зато в нём меньше мусора.

Свой файл GGUF импортируется через меню моделей — указывается путь к файлу на диске. Это удобно, если вы уже качали модели для llama.cpp и не хотите держать вторую копию. Формат GGUF одинаков для всех инструментов на движке llama.cpp, поэтому один файл обслуживает и Jan, и терминальный запуск.

## Шаг 3. Параметры модели

Панель справа от диалога содержит настройки. Практически значимые:

- **число слоёв на GPU** — прямой аналог `-ngl`, ставьте максимум, если модель влезает;
- **длина контекста** — второй по значимости потребитель памяти после весов;
- **температура и параметры сэмплинга** — влияют на текст, не на скорость;
- **системный промпт** — задаётся на уровне ассистента и наследуется новыми диалогами.

Настроек меньше, чем в LM Studio, и это ощущается ровно тогда, когда модель влезает впритык: тонких рычагов вроде типа KV-кэша или размера батча может не оказаться в интерфейсе вашей версии. Тогда остаётся либо взять модель поменьше, либо перейти на прямую работу с движком.

## Шаг 4. Локальный сервер

Jan умеет поднимать OpenAI-совместимый HTTP-эндпоинт: включается в настройках, адрес и порт видны там же. К нему подключается любое приложение, которое умеет говорить с этим API — достаточно указать локальный адрес вместо облачного и произвольный ключ.

Как и у настольных конкурентов, сервер живёт, пока открыто приложение.

## Шаг 5. Подключение облачных провайдеров

Отдельная особенность Jan: помимо локальных моделей он умеет работать с облачными по вашему ключу. Ключ хранится локально в конфигурации приложения.

Оговорка обязательная и она касается любого такого сценария: как только запрос уходит облачному провайдеру, он уходит именно ему, со всем содержимым. «Локальное приложение» в этот момент означает только то, что интерфейс работает у вас, — не то, что данные остаются на машине. Ту же развилку — своя Ollama против чужого ключа — разбирает сравнение [Persona и Jan](/blog/persona-vs-jan).

## Проверка результата

**Модель отвечает и скорость разумная.** Ориентир для модели класса 7B на дискретной видеокарте — десятки токенов в секунду. Единицы означают, что расчёт идёт на процессоре: проверьте настройку числа слоёв на GPU.

**Диалог помнит начало.** Задайте несколько вопросов подряд и вернитесь к первому. Забывание — признак маленького контекста.

**Сервер отвечает.** Если включали эндпоинт, проверьте его любым HTTP-клиентом: запрос списка моделей должен вернуть JSON, а не ошибку соединения.

## Что может пойти не так

**Модель не запускается без внятной ошибки.** Чаще всего не хватает памяти. Уменьшите контекст, возьмите более жёсткую квантизацию, при отсутствии тонких настроек — модель классом ниже.

**Импортированный GGUF не появился в списке.** Проверьте, что файл целый и что архитектура модели поддерживается версией встроенного движка. Свежие архитектуры доезжают до настольных приложений позже, чем до llama.cpp.

**После обновления пропали настройки диалогов.** Такое случается: проект развивается быстро, миграции конфигурации иногда ломаются. Держите резервную копию каталога с данными приложения перед крупными обновлениями.

**Видеокарта не используется.** Убедитесь, что установлена сборка с поддержкой вашего бэкенда и что драйверы актуальны. На AMD и Intel локальный запуск в настольных приложениях остаётся более хрупким, чем на NVIDIA.

## Что есть в LM Studio и чего нет в Jan

Таблица — главный артефакт этой статьи, потому что она делает выбор осознанным. Смотреть в ней надо на строку «исходный код»: всё остальное — цена, которую вы за неё платите.

| Свойство | LM Studio | Jan |
|---|---|---|
| Исходный код опубликован | ✗ | ✓ |
| Отполированность интерфейса | выше | ниже |
| Глубина настроек загрузки модели | больше | меньше |
| Поиск по большому открытому каталогу моделей | ✓ | ограниченный |
| OpenAI-совместимый локальный сервер | ✓ | ✓ |
| Импорт своего файла GGUF | ✓ | ✓ |
| Подключение облачных провайдеров по ключу | ✓ | ✓ |
| Управление из командной строки | ✓ | ✗ |

Вывод из таблицы простой: функционально проекты решают одну задачу, и по большинству строк разница не принципиальна. Принципиальны две — открытость и глубина настроек, и они тянут в разные стороны. Подробный разбор интерфейса закрытого конкурента — в [гайде по LM Studio](/blog/lm-studio-gayd).

Стоит развести ещё одну путаницу: открытость приложения и лицензия самих моделей — независимые вещи. Открытый клиент может запускать модель с запретительной лицензией, и наоборот. Эту тему разбирает материал об [отличии открытых весов от открытого исходного кода](/blog/otkrytye-vesa-vs-open-source).

## Частые вопросы

### Jan действительно открытый?

Исходный код проекта опубликован, и это его основное отличие от закрытых настольных клиентов. Конкретную лицензию и её условия для коммерческого использования сверяйте в репозитории — формулировки у подобных проектов пересматриваются.

### Jan быстрее или медленнее LM Studio?

При одинаковых параметрах разница невелика: оба используют один и тот же вычислительный движок. Различия в скорости обычно объясняются разными настройками по умолчанию — числом слоёв на GPU и размером контекста, а не качеством кода.

### Можно ли использовать Jan без интернета?

Да, после загрузки модели. Сеть нужна для скачивания моделей, обновлений и, разумеется, для работы с облачными провайдерами, если вы их подключили.

### Стоит ли переходить на Jan с LM Studio?

Только если вам важна открытость исходников или вы не согласны с условиями лицензии закрытого приложения. По удобству это переход вниз, и делать его «просто попробовать» — потерянный вечер.

### Чем Jan отличается от Ollama?

Форматом взаимодействия: Jan — настольное приложение с окном, Ollama — фоновый сервис с управлением из терминала. Если графический интерфейс не нужен, а модель требуется как сервис для других программ, разумнее [запускать модели через Ollama](/blog/ollama-lokalnyy-zapusk).
