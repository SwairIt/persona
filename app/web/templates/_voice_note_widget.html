{# Voice-to-note quick-capture widget. Served by ``GET /widget/voice-note`` (see :mod:`app.web.routes.voice_note_widget`) and embedded via HTMX (``
``) anywhere we want a one-click voice-memo capture button — typically the dashboard or the notes inbox. Context contract ---------------- * ``widget_id`` — short random hex string injected by the route so multiple widgets on one page can coexist without DOM-id clashes. Behaviour --------- * The button toggles between three states: idle ("Record"), recording ("Stop"), and uploading ("Saving…"). State transitions are driven by the ``MediaRecorder`` lifecycle. * On stop, the accumulated blob is POSTed as ``multipart/form-data`` to ``/api/voice-note/upload`` under the ``file`` field. The server returns either ``201`` with ``{status, note_id, transcript, file_path}`` or one of the documented error codes. * The status ``
`` is updated with the result — including a link to ``/notes#note-{id}`` on success so the operator can jump to the freshly-inserted note. * Mic-permission denial surfaces a clear human-readable error rather than swallowing the exception, so a mobile user who taps "Deny" in the OS prompt sees what happened. Styling ------- The widget uses plain CSS classes (``voice-note-…``) defined inline so the partial renders consistently whether or not the host page loaded Tailwind. The dimensions are conservative — the widget sits happily inside a 320px sidebar tile or a 1200px dashboard row. #}
