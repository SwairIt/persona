{# Mobile bottom-nav fragment — standalone (no base.html extends). The fragment is meant to be embedded at the END of via ``hx-get="/widget/mobile-bottom-nav?active={{ active_nav }}"``. It carries its own Tailwind utility classes; no extra CSS / JS file is required. The bar shows only below the ``md`` breakpoint (768 px) so the existing desktop nav keeps the screen on wider viewports. Each cell is a plain — a tap navigates as usual. The active state is computed server-side from the ``active_nav`` template variable, so the bar stays correct even with JS disabled. Active state styling: the matching icon + label flip to the accent colour and the cell gets a faint top border. We use a top border (not a background) so the bar reads as flat / native, not as a tab strip with one button "pressed in". Why ``role=navigation`` + ``aria-label``: the bar is a second nav on the page; screen readers need a label to disambiguate from the main nav up top. Safe-area padding (``pb-[env(safe-area-inset-bottom)]``) keeps the labels above the iOS home-indicator gesture area on iPhone X+. On desktop and Android the inset resolves to 0, so it's a free no-op.
