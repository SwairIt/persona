{% extends "base.html" %} {# timeline_log.html — git-style text-mode timeline log. Renders the merged event stream from ``app.timeline_log.build_log_lines`` as a monospace ``
`` block. Each line has a fixed-width left gutter
  with one ANSI-style glyph, an ISO timestamp, the ``kind`` label and
  the one-line summary body.

  Context provided by ``app.web.routes.timeline_log.timeline_log_page``:

    * ``day``            — requested ``YYYY-MM-DD`` (may be ``None`` →
                           treated as "today" in the URL builder below).
    * ``lines``          — list of ``LogLine`` dicts already filtered by
                           the active ``?kind=`` chip.
    * ``total``          — pre-filter count (informational).
    * ``shown``          — post-filter count (matches ``lines | length``).
    * ``limit``          — effective per-request cap (informational).
    * ``current_kind``   — active chip id, or ``None`` for "all".
    * ``kind_catalogue`` — tuple of ``(kind, glyph, color)`` tuples used
                           to build the chip bar without restating the
                           vocabulary here.

  Why a ``
`` block rather than the vertical-rail card layout used
  by audit_timeline.html? The brief explicitly asks for a "git-style"
  log — a flat terminal-flavoured stream. Each row therefore lives on
  exactly one line, the colour gutter aligns by virtue of the monospace
  font, and copy-paste from the browser drops into a terminal as-is.

  The chip bar is a thin self-contained piece of vanilla JS (the same
  pattern already in _timeline_filter_chips.html): clicking a chip
  mutates the ``?kind=`` URL param and reloads. No HTMX swap because
  the route owns no fragment endpoint — reloading the page is the
  simplest behaviour that survives every browser back/forward stack.
#}
